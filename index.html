myFortis Agent Portal

The Agent Portal is Fortis Healthcare's internal back office. Staff use it to set up everything a patient sees in the myFortis app and website: hospitals, doctors, specialities, tests, health-check packages, prices, slots, coupons and corporate tie-ups. Call-centre and hospital agents also use it to register patients, book on their behalf, and manage appointments, orders and refunds.

Vocabulary

Key concepts

Three service lines

Doctor / OPD
Consultations, either a Hospital Visit or a Tele/Video Consult.
PHC
Preventive Health Check-up packages, e.g. "HCU Package Emp above 50 Male".
Modality
Radiology and lab tests (MRI, CT, X-Ray, Thyroid Profile). Booked as a multi-test order.

Two ways to pay

Prepaid
"Pay Now". In the portal, the agent sends a payment link to the patient.
Postpaid
"Pay on Arrival" / Pay Later / Pay at Hospital. The booking is confirmed straight away.

Many rules are set separately for each: cancel/reschedule windows, coupon eligibility, and per-slot payment for some doctors.

Three role levels

Corporate
Pan-India, all units.
Regional
A group of units, e.g. North.
Unit
One hospital.

Roles seen: Corporate Admin, Corporate IT, Unit IT, Corporate / Regional / Unit Marketing, Corporate Finance, FD/ZD, Unit Call Center.

Learn once, read everywhere

Patterns used everywhere

Most screens are built from five patterns. Once you know them, a new module reads quickly, and any new feature should reuse them.

① List page

  • A title and a Create button (missing where records come from HIS)
  • Search with a scoped placeholder, filter dropdowns and a red ✕ Clear
  • A table with sortable headers and status pills; multi-value cells show "+8 more"
  • Some lists add a "View More Columns" side tab, which is a column chooser

② Create / Edit / View

  • The same layout is used three ways; View adds an Edit button at the top right
  • Fields are grouped in collapsible cards, two columns wide
  • Required fields are marked with a red *. Placeholders read "Enter" or "Select"
  • Footer buttons: Reset on the left; Cancel and Submit / Save / Send for Approval on the right
  • Fields that come from HIS (code, name, price, hospital) are greyed out and locked
  • Every action ends in a toast ("…created successfully!") or a confirm modal ("You are about to … Please confirm")

③ Approval (maker-checker)

Changes to doctors, specialities, service categories and configuration, PHC info and schedules, coupons and doctor schedules need a second person to approve them before they go live.

Maker editsFills the form and clicks Send for Approval
→
Pending ApprovalThe record is locked, and Edit is greyed out on the list
→
Checker reviewsOpens View, sees Preview and the Audit Trail, and writes a Review Comment
→
Approved or Sent BackApproved goes live. Sent Back returns to the maker to fix

Every approval-enabled record shows an Audit Trail table: Date & Time · Approval Status · Status · Action By · Comments.

④ Two-layer schedules

High-level (template)Day × time windows and slot length. Runs until a date (Doctor, PHC) or for a number of weeks, max 8 (Category). Needs approval.
→
Low-level (calendar)Per-date grid. Set each slot to Both / Hospital Visit / Tele / Blocked, apply to recurring weeks, add ad-hoc slots.
AvailableBooked (changes may conflict)BlockedAd-hoc (this week only)

The same model is used for Doctors, Service Categories and PHC packages. Design a schedule feature once and it applies to all three.

Reports, audit & support

Insight, traceability, and fixing integration failures.

ReportsReport builder Admins define reports: a data source, the roles allowed to see it, columns and filters. Users then run, filter and export them. Export runs in the background and finishes as a download link in the notification panel.

Define

  • Report Name, Business Object (e.g. MSREPORTS.ALL_APPOINTMENTS), Applicable Roles
  • Columns as chips, ordered by dragging
  • Filters grid: Column, Operator (= ≠ > <), Default value, Is Hidden
  • Actions: View, Edit, Clone (name and source locked)

Run

  • Filters card (Hospital, Doctor GID, Booking Status/Type/Source, UHID, date ranges…)
  • Scrollable data table with status pills
  • Export Report → "Generating…" toast → bell notification → download link
  • Report Title and Description appear on View but not on Create
  • Every filter is marked required
  • The button is "Export" in some frames and "Generate" in others

Audit TrailRead-only A global change log across content entities (categories, services, orders, specialities). Each entry opens a field-level diff.

List

  • Columns: Content ID, Content Type, Content Name, Date Timestamp, Action By, View
  • Search only; no type, user or date filters

View

  • Content ID/Type/Name, Timestamp, Action ID, Agent Name
  • Diff legend: New Old version / Deleted Updated – new version
  • "Action By" in the list vs "Agent Name" in View; the diff is a static image; the frame is 1652 px wide

Prayas / Support ServicesInternal supportBeing renamed A support console for HIS integration failures. Staff find invoices, tariffs or refunds whose API sync failed, inspect the request and response, retry, or raise a ticket.

Three record types

  • Invoices: patient registration, invoice and advance receipt. "Bill: Generated / Not Generated" filter
  • Tariffs: price-master sync for a doctor, package or service
  • Refunds: HIS approval and gateway status; partial refunds per cancelled test

Tools

  • Date scope (default Today) and Hospital filter
  • Search-by selector (Order ID, Transaction ID, UHID…)
  • Detail page: Support Timeline of API calls with JSON payloads
  • Retry API (capped: "2 Attempts left"); Bulk Retry
  • Generate Ticket, which needs investigation notes

Before you design

Gaps & open questions

Ask the business

  • What do UFC/FD Approval and Refund Workflow Status on a hospital control?
  • Who approves what? Is it based on role level?
  • What does AGP stand for? It tags the Roles and Tests & Services updates
  • Schedule horizon: is it a date ("Available Till") or a number of weeks (max 8)?
  • What triggers Auto cancelled? When does a payment link expire?
  • Who approves profile merges? What happens after 3 failed OTP attempts?
  • What happens to booked appointments when a slot is set to Blocked?
  • Does Start/Stop Consultation stay in Appointments?
  • What is the maximum number of retries in Support Services, and where do tickets go?
  • Where does a new doctor or PHC schedule start? No Create button is designed
  • Payment Gateway: how is a new gateway added, and where is the 60% alert set?
  • Should "Partially Cancelled" be its own order status?
  • Who receives which notification types? What does Undo restore?

Design gaps

  • There's no full status colour map (Inactive, Sent Back and the others aren't specified)
  • Tabs, toggles, date pickers, upload and empty states aren't in the design system
  • The slot date-strip colours (orange, red, grey) have no legend
  • Audit Trail has no filters by type, user or date, and the diff is a static image
  • Past IP Admissions and Past Orders tabs aren't designed
  • The 26-item flat sidebar has no grouping; a good candidate for UX improvement
  • Not designed yet: Dashboard, Edit Patient Profile, Add Payment Mode, and the approve/send-back screens for Reports

Inconsistencies to clean up

  • Mixed date formats: 12/10/25, 06:23 PM · 27-01-2025 · 20 Sep 2023
  • Payor vs Payer; Speciality vs Specialty; Tele Consultation vs Teleconsultation
  • "Booking Type" vs "Service Type" for the same column
  • Payment status words: Success / Paid, Pay at Hospital / Pending
  • Totals that don't add up in the booking summaries
  • Typos: Apporval, Coupn, weels, Availibility, Adress, "successfully1", "may need lead to conflict"
  • Copy-paste leftovers: two sidebar items active at once, "Speciality Icon" on PHC, "Approve Configuration"
